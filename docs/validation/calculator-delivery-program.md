## Consumer-oriented comparison contract

The [consumer boundary](cyano-integration.md) remains in force. The producer
owns paired calculation and portable data; the consumer owns gene/assembly
admission, UI rendering and biological interpretation. No model implementation
is copied into the visualizer. A producer artifact can be tested before a
public release, but production consumer admission requires the reviewed version
and its consumer-owned checks.

Comparison inputs name both supplied sequences, explicit orientation, model and
backend settings, host/calibration and candidate policy. Identity covers both
sequence hashes and all effective settings. A validated edit map relates the
two coordinate spaces; do not silently infer an ambiguous alignment. Preserve
reference, recoded and genomic coordinates separately, including strand and
supported circular-origin projection. Supplied edits must reproduce the exact
recoded sequence and preserve declared immutable segments.

Report raw scores and component terms for each candidate on each side. Compute
deltas only when both predictions are comparable under the same model/settings.
Retain mapped, inserted, deleted and unmatched candidates and every failed,
unsupported or not-evaluated observation. An absent candidate is not a score of
zero, and a candidate's coordinate gain/loss is not proof of a gained/lost
regulatory site. Any threshold-based category requires an explicit caller
policy, frozen before evaluation; no threshold optimization on final outcomes.

Portable exports preserve model/source/parameter/backend identities, score
units, host transfer warnings, verified intervals, candidate coverage, input
and edit-map hashes, and comparison status. Predicted windows remain distinct
from measured TSSs, RNA-binding annotations and transferred evidence. Tan TSSs
inform transcript context and conditional localization, not translation strength.
